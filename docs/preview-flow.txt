================================================================================
结算预览流程说明（show / preview）——与当前源码逐项对照
================================================================================

0. 范围与约定
--------------------------------------------------------------------------------

本文只描述 shop.py 当前已实现的 show 与 preview 两个查看入口的既有流程，
不引入、不建议任何产品逻辑、SQLite 表结构或公开命令的变更。其他入口
（add / decrease / set / price / remove / clear / catalog / budget）
行为保持原样，本文不展开。

文中“shop.py:行号”均以当前仓库中的 shop.py 为准（全文 568 行）。所有
结论先给源码依据，再在第 11 节列出可交叉核对的现有测试名称与其预期；
测试只作旁证，结论不以“测试已通过”代替源码。

金额单位全程为“分”，程序内部只处理整数，不出现小数或货币符号。

固定样例（本文所有输出都围绕这同一份购物车）：

    数据库文件：demo.sqlite3（由 --db 显式选定）
    products 表当前保存内容：
        P001  虚拟笔记本  单价 1200 分
        P002  虚拟马克杯  单价 2600 分   ← 注意：不是内置演示价 2500
    cart 表当前保存内容：
        P001  数量 2
        P002  数量 1

若该库尚不存在，可用公开命令复现出完全相同的保存状态（第一条命令首次
打开数据库时完成建库与演示商品初始化，见第 3 节）：

    python shop.py --db demo.sqlite3 add P001 2
    python shop.py --db demo.sqlite3 add P002 1
    python shop.py --db demo.sqlite3 price P002 2600

两条查看命令：

    python shop.py --db demo.sqlite3 preview
    python shop.py --db demo.sqlite3 show

================================================================================
1. 流程总览（六个阶段与对应函数）
================================================================================

一次 preview 或 show 调用，在 main(shop.py:531-563) 中按固定顺序经过：

    阶段                  函数                          源码位置
    --------------------  ----------------------------  ----------------
    1 参数检查            parse_args / fail             shop.py:102-126
                                                         （arity 表 60-73；
                                                          fail 54-56）
    2 数据库选择与初始化  open_db                       shop.py:129-149
    3 购物车读取          read_cart_summary             shop.py:400-425
    4 整数金额计算        read_cart_summary 循环体      shop.py:417-425
    5 满减判断（仅 preview）cmd_preview 中的一行判定    shop.py:446
    6 展示顺序与输出      cmd_show / cmd_preview /
                          write_lines                   shop.py:433-451
                                                         write_lines 428-430

入口分派在 main 中：command == "preview" 走 shop.py:553-554 调用
cmd_preview(conn)；"show" 没有专门分支，落入 main 末尾的 else
（shop.py:560-561）调用 cmd_show(conn)。两个分支都在 finally
（shop.py:562-563）关闭连接。

成功路径不调用 sys.exit，main 正常返回，进程退出码为 0；所有失败路径
都经 fail(message, code)（shop.py:54-56）：print 到 sys.stderr（print
自带一个换行）后 sys.exit(code)。

================================================================================
2. 阶段 1：参数检查（在打开数据库之前）
================================================================================

parse_args（shop.py:102-126）：

  - --db 解析（shop.py:106-115）：支持“--db 路径”（106-110）与
    “--db=路径”（111-115）两种形式，路径原样保留；省略时 db_path 为
    DEFAULT_DB（shop.py:22，即 "shop.sqlite3"，相对当前工作目录）。
    本文命令使用第一种形式，解析出 db_path = "demo.sqlite3"。
  - 子命令与参数个数（shop.py:116-121）：没有子命令、子命令未知，或
    参数个数不在 COMMAND_ARITY（shop.py:60-73）允许的元组中，一律
    fail(ERR_ARGS, 2)。
      * "preview": (0,) —— shop.py:68
      * "show":    (0,) —— shop.py:67
    即两个查看命令都不接受任何业务参数。

关键时序：parse_args 在 main 的第一行被调用（shop.py:532），open_db
在 shop.py:539 才调用。因此参数错误时数据库尚未被打开或创建
（详见第 9.1 节）。preview 没有数值类业务参数，故本入口不存在“数量/
单价格式错误”这类业务校验。

================================================================================
3. 阶段 2：数据库选择、首次创建与初始化
================================================================================

open_db(db_path)（shop.py:129-149）在同一个 try 块中依次执行：

  1) sqlite3.connect(db_path)                  —— shop.py:132
  2) CREATE TABLE IF NOT EXISTS products(...)  —— shop.py:133-136
  3) CREATE TABLE IF NOT EXISTS cart(...)      —— shop.py:137-141
  4) INSERT OR IGNORE INTO products ... CATALOG—— shop.py:142-145
  5) conn.commit()                             —— shop.py:146

任一步抛出 sqlite3.Error，都在 shop.py:147-148 被捕获并
fail(ERR_DB, 1)（ERR_DB = "数据库不可用"，shop.py:51）。

两个必须区分的事实：

  (A) 首次使用一个不存在的数据库：connect 会创建文件，两张表被建立，
      内置目录 CATALOG（shop.py:25-28）的两件演示商品被写入：
          P001 虚拟笔记本 1200
          P002 虚拟马克杯 2500
      购物车表为空。这是 CATALOG 在整条流程中的唯一用途——仅作为
      首次初始化的种子数据。

  (B) 在已有正常数据库上执行 preview / show：
      - CREATE TABLE IF NOT EXISTS 对已存在的表为空操作；
      - INSERT OR IGNORE 按主键 id 忽略已存在的商品行，不会把改过的
        价格重置回内置价（IGNORE 使冲突行保持库中原值）；
      - cmd_show（shop.py:433-437）与 cmd_preview（shop.py:440-451）
        的函数体只执行 SELECT 与标准输出写入：不创建订单、不清空
        购物车、不保存优惠状态。数据库里始终只有 products、cart 两张
        表及其主键自动索引。

因此对本文的 demo.sqlite3：P002 的保存价 2600（曾由 price 命令修改）
不会因为再次打开数据库而恢复成内置的 2500。

================================================================================
4. 阶段 3：购物车读取（show 与 preview 共用的唯一读取流程）
================================================================================

cmd_show 与 cmd_preview 的第一行都调用同一个 read_cart_summary(conn)
（shop.py:434 与 shop.py:443）。该函数（shop.py:400-425）：

  SELECT p.id, p.name, p.price, c.quantity
  FROM cart c JOIN products p ON p.id = c.product_id
  ORDER BY p.id
      —— shop.py:410-414

要点（逐条对应源码）：

  - 名称、单价、数量全部取自数据库当前内容：SELECT 的是 p.name、
    p.price、c.quantity（shop.py:411-412），流程中任何地方都不读取
    CATALOG。改价后看到的就是保存值：本文样例 P002 显示 2600，而不是
    内置演示价 2500。
  - 展示顺序由 SQL 的 ORDER BY p.id（shop.py:413）确定，即按商品编号
    升序。固定目录下即 P001 在前、P002 在后。
  - INNER JOIN（shop.py:412）：只有购物车中有记录的商品才会产生商品
    行；空购物车时 rows 为空，没有任何商品行。
  - 查询失败（例如 cart 表缺少 quantity 列）在 shop.py:415-416 捕获，
    fail(ERR_DB, 1)：此时函数不会返回，任何明细都还没有输出（输出统一
    由最后的 write_lines 完成，见第 7 节）。

================================================================================
5. 阶段 4：整数金额计算
================================================================================

read_cart_summary 的汇总循环（shop.py:417-425）：

    total_qty = 0          # shop.py:418
    total_amount = 0       # shop.py:419
    for pid, name, price, qty in rows:
        subtotal = price * qty       # shop.py:421
        total_qty += qty             # shop.py:422
        total_amount += subtotal     # shop.py:423
        lines.append(f"{pid} {name} {price} {qty} {subtotal}")  # 424

  - price、qty 是从 SQLite INTEGER 列读出的 Python int（单字段至多
    19 位，上界常量 MAX_QUANTITY = MAX_PRICE = 9223372036854775807，
    shop.py:31、34）。
  - 乘法（shop.py:421）与两处累加（shop.py:422-423）全部使用 Python
    任意精度整数，不写回数据库，也不做任何范围检查。因此即使行小计或
    合计超过 SQLite INTEGER 保存上限，仍得到精确整数并按十进制原样
    输出（见第 8.3 节）。
  - 商品行字段顺序固定为“编号 名称 单价 数量 小计”（shop.py:424）。

函数返回 (lines, total_qty, total_amount)（shop.py:425），即商品行
列表、优惠前总数量、优惠前总金额。show 与 preview 拿到的是完全相同的
这三项结果。

================================================================================
6. 阶段 5：固定满减判断（仅 preview）
================================================================================

cmd_preview（shop.py:440-451）在共用读取之后，用一行完成全部优惠逻辑：

    discount = DISCOUNT_AMOUNT if total_amount >= DISCOUNT_THRESHOLD else 0
        —— shop.py:446
    常量：DISCOUNT_THRESHOLD = 5000（shop.py:37）
          DISCOUNT_AMOUNT    = 500 （shop.py:38）

规则（均直接来自这一行表达式）：

  - 比较运算是 >=：优惠前总金额低于 5000 分不优惠（discount = 0）；
    恰好 5000 分与超过 5000 分都减 500 分。
  - 优惠是固定金额的一次性判定，没有第二档、没有倍数、不按比例：总金额
    即使达到“多个 5000”，discount 仍只有一个 500（不存在多档叠加）。
  - 应付金额就是普通整数减法：
        应付金额 = total_amount - discount    —— shop.py:450
    因门槛 5000 高于优惠额 500，应付金额不会为负。
  - 判定只发生在本次进程的内存中，结果不入库（第 3(B) 节）。

cmd_show 不含这一阶段：它只追加“总数量”“总金额”两行
（shop.py:435-436），所以 show 永远展示优惠前的原始金额。

================================================================================
7. 阶段 6：展示顺序、字段空格与末行换行
================================================================================

cmd_preview 在商品行之后严格按以下顺序追加四行（shop.py:447-450）：

    总数量 {total_qty}
    总金额 {total_amount}
    优惠金额 {discount}
    应付金额 {total_amount - discount}

cmd_show 只追加前两行（shop.py:435-436），即“总数量”“总金额”。

两个命令最后都调用 write_lines(lines)（shop.py:437、451），其实现只有
一行（shop.py:430）：

    sys.stdout.write("\n".join(lines) + "\n")

由此确定的字节级格式：

  - 每个字段、标签与数值之间恰好一个 ASCII 空格：来自各 f-string 中
    单个 " "（商品行 shop.py:424；汇总行 shop.py:435-436、447-450），
    没有对齐填充、没有千位分隔符、没有货币符号。
  - 相邻两行之间恰好一个换行符 "\n"；全部行准备好后一次性写出
    （write_lines 注释，shop.py:429：失败路径不会出现部分明细）。
  - 末行之后恰好再补一个 "\n"，因此输出总是以一个换行结束，且不会有
    多余空行（不会以两个换行结束）。
  - 数字用 Python int 的默认十进制字符串形式：无小数、无科学记数法。
  - 空购物车时 lines 仍包含汇总行，故 preview 仍输出四行、show 仍输出
    两行（不是零字节）。

8. 固定样例的完整预期输出（逐项可核对）
================================================================================

8.1 手算核对
--------------------------------------------------------------------------------

    P001 小计 = 1200 × 2 = 2400
    P002 小计 = 2600 × 1 = 2600
    总数量     = 2 + 1        = 3
    优惠前总额 = 2400 + 2600  = 5000
    5000 >= 5000 成立         → 优惠金额 = 500（只减一次）
    应付金额   = 5000 - 500   = 4500

8.2 python shop.py --db demo.sqlite3 preview
--------------------------------------------------------------------------------

标准输出（6 行；字段间单个空格；末行“应付金额 4500”后恰好一个换行）：

    P001 虚拟笔记本 1200 2 2400
    P002 虚拟马克杯 2600 1 2600
    总数量 3
    总金额 5000
    优惠金额 500
    应付金额 4500

写成带显式换行的形式即：

    P001 虚拟笔记本 1200 2 2400\n
    P002 虚拟马克杯 2600 1 2600\n
    总数量 3\n
    总金额 5000\n
    优惠金额 500\n
    应付金额 4500\n

标准错误：空（0 字节）。退出码：0。

商品行为编号升序（P001、P002）；小计分别为 2400、2600；汇总依次为
总数量 3、总金额 5000、优惠金额 500、应付金额 4500。

8.3 python shop.py --db demo.sqlite3 show
--------------------------------------------------------------------------------

标准输出（4 行；同样单空格、末行一个换行）：

    P001 虚拟笔记本 1200 2 2400
    P002 虚拟马克杯 2600 1 2600
    总数量 3
    总金额 5000

显式换行形式：

    P001 虚拟笔记本 1200 2 2400\n
    P002 虚拟马克杯 2600 1 2600\n
    总数量 3\n
    总金额 5000\n

标准错误：空（0 字节）。退出码：0。

show 的汇总只有前两项（总数量、总金额），没有“优惠金额”“应付金额”：
它不经过第 6 节的满减判定，始终展示优惠前原始金额。两次查看使用同一
读取流程，所以两条命令的商品行与前两行汇总逐字相同。

8.4 两次查看都不改变样例数据
--------------------------------------------------------------------------------

preview 与 show 的函数体（shop.py:433-437、440-451）只做 SELECT 与
stdout 写入。对 demo.sqlite3 连续执行任意次数后，保存内容仍为：

    products: (P001, 虚拟笔记本, 1200)、(P002, 虚拟马克杯, 2600)
    cart:     (P001, 2)、(P002, 1)

open_db 中的 IF NOT EXISTS / INSERT OR IGNORE 对已存在对象与行均为空
操作（第 3(B) 节），不改价格、不清购物车；preview 也不新增订单表或
保存优惠状态的任何对象。反过来，若用 price 改价或用 set/decrease 调量，
下一次查看会按新保存值重新计算，因为读取只认数据库当前内容（第 4 节）。

================================================================================
9. 边界情形（规则在源码中的依据）
================================================================================

9.1 满减门槛的三档边界
--------------------------------------------------------------------------------

由 shop.py:446 的 >= 与固定 500 唯一确定：

    优惠前总金额 4999（< 5000） → 优惠金额 0，应付 4999
    优惠前总金额 5000（= 门槛） → 优惠金额 500，应付 4500
    优惠前总金额 5001（> 门槛） → 优惠金额 500，应付 4501
    优惠前总金额 10000（两倍门槛）→ 优惠金额仍只有 500，应付 9500
                                 （达到多个门槛也只减一次，不叠加）

9.2 空购物车
--------------------------------------------------------------------------------

rows 为空时循环不执行（shop.py:420），total_qty 与 total_amount 保持
初值 0（shop.py:418-419）。preview 输出四行、四项全为零：

    总数量 0
    总金额 0
    优惠金额 0
    应付金额 0

（0 < 5000，discount = 0。）show 在同一状态下只输出“总数量 0”与
“总金额 0”两行。

9.3 零单价商品
--------------------------------------------------------------------------------

单价允许为零（MAX_PRICE 注释，shop.py:33-34；price 命令的非负校验
shop.py:219-233）。零单价商品只要购物车中有记录，就照常出现在 JOIN
结果中：商品行保留编号、名称、单价 0 与真实数量，小计 0×qty = 0，数量
仍计入总数量（shop.py:421-424）。即“零单价仍显示数量”，行不会被省略。

9.4 小计或合计超过 SQLite 整数保存上限
--------------------------------------------------------------------------------

SQLite INTEGER 上界为 9223372036854775807（shop.py:31、34）。单价、
数量各自落库时都不超过该上界，但 price*qty 与其累加在 Python 侧完成
（shop.py:421-423），不受该上界约束：

  - 单价、数量都取上界、单价为 1 时：行小计等于上界（仍合法），总数量
    18446744073709551614、总金额 18446744073709551614 已越界，仍完整
    显示；总额达到门槛，优惠 500，应付 18446744073709551114。
  - 单价为 2 时：行小计本身即 18446744073709551614（越界），总金额
    36893488147419103228、应付 36893488147419102728，同样完整显示，
    优惠仍只减一次 500。
  - 极端情形单价、数量同上界时，行小计为
    85070591730234615847396907784232501249（39 位精确整数），show 与
    preview 都按完整十进制输出，不报“超出范围”、不报数据库不可用，
    也不出现科学记数法或截断。

================================================================================
10. 异常路径（仅本查看入口）
================================================================================

两条查看命令共享同一入口时序与同一读取函数，故以下契约对 preview 与
show 一致；额外参数一例以 preview 表述。

10.1 preview 带额外参数：参数错误，退出码 2，且在打开数据库前拒绝
--------------------------------------------------------------------------------

命令形态（任意额外参数，一个或多个）：

    python shop.py --db demo.sqlite3 preview extra

结果：

    标准输出：空（0 字节，没有任何明细）
    标准错误：参数错误\n        （仅此一行，文字后一个换行）
    退出码：2

依据：preview 的合法参数个数为 (0,)（shop.py:68），个数不符时
parse_args 在 shop.py:120-121 调用 fail(ERR_ARGS, 2)；ERR_ARGS =
"参数错误"（shop.py:40），换行来自 fail 中的 print（shop.py:55）。
parse_args（shop.py:532）先于 open_db（shop.py:539），所以即使 --db
指向一个尚不存在的路径，该数据库文件也不会被创建；指向一个已损坏的
已有库时，也仍然优先报参数错误且不触碰其内容。

10.2 数据库无法创建、打开或读取：数据库不可用，退出码 1
--------------------------------------------------------------------------------

三种情形：

  (1) 无法创建：--db 指向不存在的父目录（如 no_such_dir/x.sqlite3），
      connect/建表/commit 抛 sqlite3.Error；
  (2) 无法打开：路径是一个已存在的目录等不可作为 SQLite 文件打开的目标；
  (3) 无法读取：数据库可以打开，但明细查询失败（如 cart 表缺少
      quantity 列）。

结果（三种情形相同）：

    标准输出：空（0 字节，没有任何商品行或汇总行）
    标准错误：数据库不可用\n      （仅此一行，无异常堆栈）
    退出码：1

依据：

  - 情形 (1)(2) 在 open_db 的 try 块（shop.py:131-146）内抛出，由
    shop.py:147-148 捕获，fail(ERR_DB, 1)；此时连接尚未返回，流程
    根本没有进入读取阶段。
  - 情形 (3) 在 read_cart_summary 的 shop.py:415-416 捕获并
    fail(ERR_DB, 1)；失败发生在 write_lines 之前，lines 不会被写出，
    因此没有部分明细。无法读取的购物车不会被当作空购物车。
  - ERR_DB = "数据库不可用"（shop.py:51），换行同样来自 print
    （shop.py:55）。

11. 现有测试对照（写明测试名称与预期；仅作旁证，依据仍为源码）
================================================================================

下列测试均可在项目目录用 python -m unittest <模块名> 运行。预期文字
是各测试文件内手写的独立字面量。

test_preview.py（ShopPreviewTests）：
  - test_preview_sample_cart：两件 P001、一件 P002（内置价 1200/2500）
    时 preview 为两行商品 + 总数量 3 / 总金额 4900 / 优惠金额 0 /
    应付金额 4900；连续两次输出各自逐字相同。
  - test_preview_threshold_boundary_and_no_stacking：仅一件 P002，经
